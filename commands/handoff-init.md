# handoff-init — 導入と更新

このプロジェクトに claude-remote-handoff を導入する。既に入っていれば版を比べて更新する。

配布元は固定: `https://github.com/Taichis-K/claude-remote-handoff`

**呼び出し名**: このファイルを `~/.claude/commands/` へ置いた場合は `/handoff-init`、
プラグイン経由で入っている場合は `/claude-remote-handoff:handoff-init`
（プラグインのコマンドは常にプラグイン名で名前空間が付く）。

## この文書の読み方

**手順を機械的になぞる文書ではない。** 現場の状態は一通りではないので、
場合分けを網羅した指示は書いていない。代わりに次の3つを書いてある。

1. **ゴール** — 何が達成されれば導入できたと言えるか
2. **不変条件** — 状況にかかわらず**絶対に破ってはいけないこと**。判断の余地は無い
3. **人に聞くこと** — あなたが決めてはいけないこと

**状況に合わせた判断はあなたがする。** 部分的に登録が残っている、同じ登録が2つある、
旧版の配置先を指している、系統が変わる — こうした状態は、
**不変条件を守る限り、あなたが直してよい**。
ただし何が起きているか分からないなら、**推測で書かずに聞くこと**。

## ゴール

次がすべて満たされた状態にする。

1. **フックが5つ、過不足なく1組だけ効いている**
   （PreCompact 1 / SessionStart 3 / Stop 1。**多くても少なくてもいけない**）
2. フックの**実体がこのプロジェクトの中にあり**、配布元の最新リリースと同じ版である
   （プラグインが供給している場合は、プラグインが最新であればよい）
3. `.claude/handoff-config.json` が**この環境に合った値**で存在する
4. `Edit(.claude-handoff/**)` の許可ルールがある
5. `.gitignore` に4エントリがある（gitリポジトリのとき）
6. **できなかったことが利用者に正しく伝わっている**

「5つが1組だけ」は、フックが**複数の場所からマージされる**ので数え方に注意が要る。
詳しくは §1。

## 不変条件（破らない）

これらは状況によらない。**迷ったらこちらを優先する。**

1. **取得したファイルを実行しない。** 読む・コピーする・参照するだけ。
   `setup.ps1` / `setup.sh` も実行しない（このコマンドが同じ結果をファイル編集で作る）
2. **書く前に、書き込み先の実体パスを確かめる**（§0-2）
3. **`.claude/settings.json`（共有側）と ユーザーレベルの `settings.json` を書き換えない。**
   コミットされる、あるいは全プロジェクトに効く設定なので、必要なら**手で直してもらう**
4. **既存のフックエントリを、承認なしに消さない。** 消す必要があると判断したら、
   **何をなぜ消すかを示して承認を得る**
5. **`settings.local.json` は「退避 → 編集 → 検証 → 必要なら復元」**の外で書かない（§4）
6. **二重発火を残さない。** 5つが1組だけになる見込みが立たないなら、**書かずに相談する**
   （不一致のまま足すと、1ターンに2回走る）
7. **配布物は可動する枝から取らない。** タグで固定し、**利用者の承認を得てから**書く（§2）
8. **登録するスクリプトは、自分で置いた確認済みのものにする。**
   「既にあるから」で登録しない（中身が欠けている・書き換わっていることがある）
9. **できなかったことを「できた」と報告しない。** とくに
   「登録は正しいのにフックが動かない」状態（§1-3）を導入成功として報告しない

## 0. 最初に確かめること

### 0-1. `~/.claude` の読み替え

**環境変数 `CLAUDE_CONFIG_DIR` が設定されていたら、この文書の `~/.claude` は
すべてそのディレクトリを指す。** 設定ディレクトリはこの変数で移設でき、
移設すると `~/.claude` は使われない。フック本体（`handoff-common.ps1` / `handoff-common.sh`）も
同じ変数を見ている。

読み替え対象: ユーザーレベルの `settings.json`、`commands/handoff-init.md`、
`claude-remote-handoff/handoff-config.json`。

読み替えないと、**移設先にある既存の登録を見落として二重発火させる**。

### 0-2. 書き込み先の安全確認

**ファイルを作る・書き換える・削除する前に、対象ごとに必ず行う。例外は無い。**

1. 対象と、そこへ至るすべてのディレクトリについて、
   **symlink / junction / reparse point を解決した実体パス**を求める
2. その実体が**書いてよい場所から外れていないか**を見る

**symlink があること自体は問題ではない。** 見るのは「**実体が外に出ていないか**」だけ
（macOS では `/tmp` も `/var` も `/private/...` への symlink なので、
symlink を理由に止めると §2 の clone すらできない）。

| 書き込み先 | 書いてよい場所 | 外れていたら |
| --- | --- | --- |
| プロジェクト内のすべて（`.claude/hooks/...` / `settings.local.json` と退避先 / `handoff-config.json` / `.gitignore`） | プロジェクトのルート配下 | **中断する** |
| `~/.claude/` の下（コマンド自身・設定テンプレ） | `~/.claude/` の配下 | **実体パスを見せて確認する**（dotfiles 管理で外へ張っているのは正常な構成。`~/.ssh/config` のような無関係なファイルなら利用者が止められる） |
| clone 用の一時ディレクトリ | OSの一時領域 | **プロジェクトの中なら中断する** |

これは**表に挙がっていない書き込みにも適用する**。守りたいのは
「リンク先の実体を書き換えて、対象外のファイルを壊さないこと」である。

### 0-3. 信頼境界（利用者に正しく伝えること）

このコマンドは配布元からファイルを取得し、**このマシンのフックとして登録する**。
フックは以後、毎ターンの Stop / SessionStart で**利用者の権限で自動実行**される。

したがって安全性の根拠は「**配布元アカウントを信頼できること**」だけである。

- 版をタグで固定するのは、**可動する枝が知らないうちに差し替わる**事故を防ぐためであって、
  取得物が正当であることの証明ではない
- 配布元の GitHub アカウントが侵害されていれば、タグ名・commit SHA・`VERSION` は
  **すべて攻撃者が作れる**
- 署名検証も既知 SHA の照合も行わない（鍵や既知 SHA の入手経路が同じ問題を抱えるため、
  この方式の信頼境界は動かせない）

§2 の確認は「**この配布元を信頼して、フックとして自動実行させてよいか**」を尋ねるものである。
**「検証しました」「安全性を確認しました」と説明しないこと。**

### 0-4. Claude Code のバージョン

`claude --version` が **v2.1.163 以上**か確認する。下回るなら中断し、更新を促す。

## 1. いまフックがどう効いているかを調べる

ゴールの1（5つが1組だけ）を判断するために要る。**フックは複数の場所からマージされる**ので、
1か所だけ見ても分からない。

### 1-1. 登録がありうる場所（すべて見る）

| 場所 | このコマンドの扱い |
| --- | --- |
| `.claude/settings.local.json` | **ここに書く** |
| `.claude/settings.json`（共有側） | 読むだけ。**書き換えない**（不変条件3） |
| `~/.claude/settings.json`（ユーザーレベル） | 読むだけ。**書き換えない**。`args` が `${CLAUDE_PROJECT_DIR}` 相対なので全プロジェクトに効くが、**指す先はそのプロジェクトの中**なので、**フック本体はプロジェクトごとに要る** |
| プラグイン（`claude plugin list`） | 操作しない。更新は案内のみ（§6-2） |
| **managed settings**（組織配布） | 読めるなら読む。**置換ではなくマージされる** |
| `claude --plugin-dir` / `--plugin-url` | 一覧に出ない。**使っていそうなら利用者に聞く** |

最後の3つは見落としやすく、**見落とすと「登録0件」と誤判定してもう1組足し、
二重発火させる**。1か所目で見つからなかったときほど、残りを丁寧に見ること。

**プラグインがこのOSでフックを供給しているか**は、有効かどうかだけでなく**OSでも決まる**。
プラグインの `hooks.json` は `powershell.exe` 前提なので、
**macOS / Linux では有効でもフックは動かない**（静かに失敗する）。

### 1-2. エントリの同一性

**(イベント名, matcher, type, command, args) の5つ組**が全部一致したときだけ「同じもの」とみなす。

- **`type` を落とさない。** `"type": "prompt"` のような別種を「ある」と誤判定すると、
  **動かないまま導入済みと報告する**ことになる
- matcher を持たないイベント（PreCompact / Stop）では、**「matcher 無し」も1つの値**として区別する
- **件数で判断しない。** `resume` が2件で `Stop` が欠けていても5件になる
- **「その種類が1件以上ある」でも足りない。** 同じものが2件あれば1ターンに2回走る
- `claude-remote-handoff` を**指さない**フック（他のツールのもの）は対象外。数に含めない

期待する形は §3 の3つのスニペットのうち**1つ**。`ps` 系統には `powershell.exe` 版と
`pwsh` 版の**2つ**があるので、「系統が同じ」だけでは相手が決まらない。
**既存の登録があるなら、その `command` と同じスニペット**を相手にする。

### 1-3. 「登録は正しいのに動かない」状態

**登録の形が合っていても、これらに当てはまれば動いていない。**
気づかずに「導入済み」と報告しないこと（不変条件9）。

- `disableAllHooks: true` がどこかにある → **フックは1つも動かない**
- `command` がこのOSで実行できない（例: macOS で `powershell.exe`）
- **`sh` 版なのに `jq` が無い** → error.log に1行残すだけで何もせず終了する（画面には出ない）
- 登録が指すスクリプトが**実在しない**（系統を乗り換えた後など）

見つけたら報告する。直せるものは直し、直せないもの（`disableAllHooks` や `jq` の導入）は
**具体的な操作を伝える**。

### 1-4. 判断のしかた

ここまでで「実際にどう効いているか」と「期待する形」が出そろう。差を埋める。

- **足りない** → 足す
- **同じものが2つ以上ある** → 承認を得て1つだけ残す
- **形が違う**（旧パス・`type` 違い・`-WindowStyle Hidden` の有無）→
  承認を得て置き換える。**機能に影響するかも伝える**
  （`-WindowStyle Hidden` は v0.1.4 で入った点滅対策で、**無くても動作する**）
- **プラグインとプロジェクト設定の両方にある** → 二重発火している。どちらかに寄せてもらう。
  **推奨はプロジェクト設定側**（OSを問わず同じ挙動になる）。
  プラグインを止めるなら `claude plugin disable claude-remote-handoff --scope <値>` を案内する
- **共有側・ユーザーレベル・managed にある** → **書き換えない**（不変条件3）。
  内容を見せて手で直してもらう。
  ただし**意図して全プロジェクト向けに置いている場合は、その登録はそのままでよい**。
  その場合は**プロジェクト側に登録を足さない**が、
  **フック本体は §2・§3 で必ず置く**（登録は `${CLAUDE_PROJECT_DIR}` 相対なので、
  **指す先はこのプロジェクトの中**である。置かないと5本とも
  「存在しないスクリプト」を毎ターン叩き続ける ＝ §1-3 の状態になる）。
  配置したうえで §4〜§7 を行う
- **`--plugin-dir` / `--plugin-url` を使っている** → 版の比較も `plugin update` の案内も効かない。
  どうしたいかを聞く

**承認が得られず、5つが1組だけにできる見込みが立たないなら、フックには触れない**（不変条件6）。
そのうえで**許可ルール・閾値設定・`.gitignore` だけ進めてよいか**を尋ねる。
これらはフック登録と独立なので、**動いている環境を巻き添えにして何もせず終わるほうが損**である。
進めた場合は、**フック登録が意図した構成になっていないこと**を報告に書く。

## 2. 配布物の取得（版を固定する）

フックを配置・更新する必要があるとき、およびプラグインの版を比べるときに行う。
§1-4 で「設定だけ進める」ことになった場合は不要。

**default branch を取らないこと。** 可動する枝を取ってフックとして登録すると、
配布元が差し替わった内容が次の Stop / SessionStart で自動的に実行される。

1. リリースタグの一覧を取り、**最新のタグ**を選ぶ:

   ```
   git ls-remote --tags https://github.com/Taichis-K/claude-remote-handoff
   ```

   タグは `v<数>.<数>.<数>` 形式。**数値ごとに比較する**
   （文字列順では `v0.1.10` が `v0.1.9` より前になる）。この形式に合わないタグは候補から外す。

2. そのタグを指定して一時ディレクトリへ浅く clone する。
   **`-c core.autocrlf=false` を必ず付けること**:

   ```
   git -c core.autocrlf=false clone --depth 1 --branch <タグ> https://github.com/Taichis-K/claude-remote-handoff <一時ディレクトリ>
   ```

   配布元には `.gitattributes` があるので通常はこれ無しでも LF のままだが、
   **付けておけば古いタグを取るときも守られる**。外すと、`core.autocrlf=true` の環境で
   `.sh` が CRLF になり、macOS / Linux で **`$'\r': command not found`** になって動かない
   （過去のリリースで実際に起きた事故）。この指定はコマンド1回きりで、利用者の設定は変えない。

3. **タグと `VERSION` を突き合わせる**:
   - タグ名の**先頭の `v` を1つだけ取り除く**（`v0.1.5` → `0.1.5`）
   - `<一時ディレクトリ>/hooks/VERSION` の中身から**前後の空白と改行を取り除く**
   - この2つが**文字列として一致すればよい**
     （タグ `v0.1.5` と `VERSION` の `0.1.5` は**一致である**）
   - 一致しないときだけ**中断**して報告する

4. **利用者に提示して確認を取る**（タグ名・commit SHA・`VERSION` の中身）。
   このとき **これらは真正性の検証結果ではない**ことを併せて伝える（§0-3）。
   尋ねるのは「**この配布元を信頼して、フックとして自動実行させてよいか**」である。

   **承認されるまでプロジェクトへ書き込まない。**

clone したツリーのルート直下に `hooks/`（`VERSION` / `ps` / `sh`）と `commands/` がある。
**この中のスクリプトは実行しない。** 終わったら一時ディレクトリを削除する。

### 2-1. 手順そのものの版を先に合わせる

**このコマンドはフックを更新するが、放っておくと手順の側（このファイル）は古いままになる。**
契約が変わるリリースでは**フックだけ新しく手順は古い**状態になり、
新しいフックに古い形式の設定を与えてしまう。**プロジェクトへ書く前に**ここで止める。

確かめるものは**2つあり、独立している**。片方だけ見ると取りこぼす
（ユーザーレベルに置いた**最新のコマンド**で、フックは**古いプラグイン**が供給している、
という組合せが実在する）。

- **手順の版** — いま実行しているこのファイルの出どころ
  - **取得したタグに `commands/handoff-init.md` が無い場合**（このコマンド自体が
    まだリリースに含まれていない版を取ったとき）は、**比較しない**。
    その旨を報告して**先へ進む**。比較対象が無いことを「違う」と扱って
    置き換えたり終了したりしないこと
  - `~/.claude/commands/` に置いたもの: clone した `commands/handoff-init.md` と**内容比較**する
    （版番号を持たないので内容で見る）。
    **比較の前に行末の改行コードと各行の末尾の空白を正規化する**
    （手元のファイルがエディタや以前のコピー経路で CRLF になっていることがあり、
    正規化しないと中身が同じでも毎回「違う」と判定される）。
    違うなら報告して置き換えを確認し、**置き換えたらそこで終了**して
    「新しい手順で最初からやり直してください」と伝える。
    承認されなければ**何も書かずに終了**する。古い手順のまま続ける選択肢は用意しない
  - プラグインが供給しているもの: **プラグインの版がそのまま手順の版**になる。下と同じ
- **フックの版** — プラグインがフックを供給している場合、`claude plugin list` の版とタグを比べ、
  古ければ §6-2 の更新手順を案内して**終了する**。
  **実行経路とは関係なく確かめる**（macOS / Linux ではプラグインのフックは動かないので
  フックの供給元にはならないが、**手順がプラグインから来ていれば版を確かめる必要がある**）

## 3. フック本体の配置と、登録の内容

プラグインがフックを供給していて、それで足りているなら**配置も登録もしない**。

### 3-1. 配置

**配置するかどうかに関わらず、まず `.claude/hooks/claude-remote-handoff/` に §0-2 を適用する。**
ここが外部への symlink だと、**そこにあるスクリプトを登録する**ことになり、
次のターンから**プロジェクト外のコードが自動実行される**。

**系統を選ぶ**（`ps` = `powershell.exe` / `pwsh`、`sh` = 要 `jq`）。

- **既に動いている系統があるなら、それを使う。** 後から `jq` を入れたからといって乗り換えない
- 乗り換えるなら、**新しい系統のスクリプトを置いてから**登録を差し替える。
  順序を逆にすると、存在しないスクリプトを毎ターン叩いて静かに失敗する
- 新規なら: **Windows** → `ps`。**macOS / Linux** → `jq` があれば `sh`、
  無ければ `pwsh` を確認して `pwsh`（`ps` ディレクトリを使う）。
  どちらも無ければ**中断**し、`jq` か PowerShell 7 の導入を促す
  （macOS Sequoia 以降は `/usr/bin/jq` が同梱）

**配置を省いてよいのは、「登録が既に正しく、その系統のスクリプトが実在し、版も同じ」ときだけ**。
**これから新しく登録するなら、版が同じでも必ず置き直す**（不変条件8。
そこにある配置は前回の中断や手作業で残ったもので、中身が欠けていることがある）。

置き方:

1. **`sh` 版を置くなら、コピー前に `.sh` に CR が含まれていないことを確かめる。**
   1つでもあれば**配置せず中断**し、clone のやり直しを伝える。
   **CR を自分で取り除いて配置しない**（取得物を書き換えると、何を置いたのか分からなくなる）
2. **先にスクリプト**をコピーする
   （`<一時ディレクトリ>/hooks/ps/` または `/sh/` → `.claude/hooks/claude-remote-handoff/ps/` または `/sh/`）
3. **すべて成功してから最後に `VERSION`** を
   **`.claude/hooks/claude-remote-handoff/VERSION`** へコピーする
   （**`ps/` や `sh/` の中ではない**。ここが唯一の版の記録で、
   場所を間違えると次回「版が分からない ＝ v0.1.3 以前」と誤判定され、毎回置き直しになる）。
   逆にすると、途中で失敗したとき「中身は新旧混在なのに版だけ最新」になり、
   次回は配置が省かれて**壊れたまま直らない**

`hooks.json` はプラグイン用なのでコピーしない。`.claude-handoff/` には触れない。

**導入済み版が v0.1.3 より前なら、入れ替える前に**次を確認する。

- `.claude-handoff/latest.json` が**未消費のまま残っていないか**。残っていれば

## 4. `settings.local.json` への書き込み（1回で済ませる）

**フック登録（§3-2）と許可ルール（§5）は、この1つの手順でまとめて書く。**
別々に書くと退避の外で壊す経路ができる。

**フックを1件も足さない場合でも、この手順を通る。** 許可ルールはプロジェクトごとに要るためで、
飛ばすとフックが動いていても Stop のたびに許可プロンプトで止まる。

1. **安全確認**（§0-2）を `.claude/settings.local.json` と**これから作る退避先**の両方に行う
2. **元の状態を控える**:
   - **ファイルがある**: **`.claude/settings.local.json.bak-<年月日時分秒>`** へ退避し、
     読み込んだ**JSON全体を控える**（後で差分を取る）。
     **固定名 `.bak` にしないこと** — 前回の中断で残った退避や別用途のファイルを壊すか、
     避けた結果**「戻す先が今回の退避ではない」**という事故になる（古い内容へ巻き戻して
     現在の `permissions.deny` を失う）。既にある `.bak` や別日時のものには**触れない**
   - **ファイルが無い**: 退避は作らず「**元は不存在**」と控える
3. マージする:
   - §3-2 のエントリのうち**足りないもの**（足さない場合はゼロ件）
   - `permissions.allow` への `Edit(.claude-handoff/**)`（§5。**常に**）
   - **既存を消さない。** 唯一の例外は §1-4 で**削除の承認を得たエントリ**
4. 書き込み後に検証する。**キーの有無だけを見ないこと**:
   - JSON として読めるか
   - **2 で控えた元のJSONと構造ごと比較**し、差分が
     **3 で意図的に行った変更だけ**であること。それ以外があれば失敗。
     **キー名が残っていても値や配列の中身が変わっていれば失敗**である
     （例: `permissions.deny` が空配列になる。キーは残るので「キーがある」検査では見逃す）
   - **§1 の調べ直しを、書いた後のファイルに対して行う**。
     **5つが1組だけ**になっているか。件数や「種類ごとにあるか」で済ませないこと
     （マージで重複を作った場合に通ってしまう。
     また「起きるはずの削除が起きなかった」は構造比較には現れない）
5. 検証に1つでも失敗したら、**元の状態へ戻して中断**し、何が起きたか報告する:
   - **今回作った退避ファイル**を戻す（他の `.bak` は使わない）。
     戻したら**今回の退避も消す**（元に戻っているので用は無い）。
     戻すのに失敗したときだけ**残してパスを報告する**
   - 「元は不存在」なら、作ったファイルを**削除する**。
     壊れたJSONを残すとプロジェクト設定が読めなくなる
     （「戻す物が無いのでそのまま」は**不可**）
6. **すべて成功してから、今回作った退避ファイルだけ**を削除する（他の `.bak` には触れない）

### 4-1. 書き込みが権限で拒否されたとき

**settings への書き込みは「任意コマンドの自動実行を設定する行為」なので、権限承認や安全分類器に
拒否されることがある。** 環境が下した判断であり、**通常の処理失敗（書式の誤り・I/Oエラー）とは
別のもの**として扱う（macOS の auto mode で `[Self-Modification]` として拒否された実測報告がある。
同じ版の同じ内容が別環境では通っているので、**環境差**と見てよい。
内容を変えて通そうとする意味は無い）。

**回避策を探さないこと。** 1つの経路で拒否されたら、**別のツールや別の書き方で再試行しない**
（編集ツールが駄目だったからシェル経由、シェルが駄目だったから一時ファイルと `cp`、など）。
拒否は利用者の環境が下した判断で、**迂回はその判断を無効化する**。
実測報告では、経路を変えても拒否され、**3回試して3回とも止まった**。

**この節は「書き込みが実行される前に拒否された」場合の手順である。**
§4 の 5（検証失敗後の復元）の書き込みが拒否された場合は、**下の「復元が拒否されたとき」**を見る。

拒否されたら次のようにする。**ここで止まるのは失敗ではない。**

1. **ファイルが元のままであることを読んで確かめてから、今回作った退避ファイルを消す。**
   実行前に拒否されていれば中身は変わっていないが、**確かめずに消さない**。
   元と違っていたら**退避は消さず**、下の「復元が拒否されたとき」に従う。
   退避が残ると、`.gitignore` の `.claude/settings.local.json` に `*` が無く、
   他に退避を覆う規則も無い環境では `git add -A` で拾われる
   （§7 で `*` 付きを勧めているのはこのため）
2. **マージ後の完成形JSONを全文提示する。** 差分や「ここに足してください」ではなく、
   **そのまま保存すれば終わる形**にする。手で組み立てさせると `args` の綴りを間違えて
   §1-3 の「登録は正しく見えるのに動かない」状態になる。
   §5 の許可ルールは同じファイルなので、**このJSONに含めておく**
3. **フック登録以外は進める。** §6（閾値設定）と §7（`.gitignore`）は別のファイルなので、
   同じ拒否には当たらないことが多い。フックが登録できないことを理由に、
   **できるところまで止めない**
4. **§9 で「今回予定した settings の変更は未適用」と報告する。**
   **一律に「登録は未完了」「全部動かない」と書かないこと。** §4 は
   **フックを1件も足さない場合でも通る**手順で、拒否されたのが許可ルールだけということもある。
   §1 の調査結果に基づいて**分けて**書く:
   - **既にある登録**（そのまま効き続ける。ユーザーレベルの登録もここに含む）
   - **足りないままの登録**（何が足りないか）
   - **許可ルールが未適用かどうか**（未適用なら、Stop のたびに許可プロンプトで止まる）

   **「5本とも1度も動かない」と書いてよいのは、§1 の調査で登録がどこにも0件だったときだけ**。
   その場合はフック本体を置いても1度も動かない（§1-3 の状態）。
   いずれにせよ、導入できたと報告しないこと（不変条件9）
5. 利用者がJSONを適用したあと、**`/hooks` で5エントリが見えるか確認**してもらう
   （見えなければ Claude Code を再起動）と伝える

#### 復元が拒否されたとき

§4 の 5 で「検証に失敗 → 元へ戻す」の書き込みまで拒否された場合、
**ファイルは元の内容ではない**。このときは:

- **退避ファイルを消さない。** これが元の内容を持つ唯一の複製である
- **退避のパスと、いま `settings.local.json` がどうなっているか**を報告する。
  「戻せていない」ことを明示する（不変条件9）
- 利用者に**退避で上書きして戻してもらう**（コマンド例を具体的に示す）。
  自分で戻す経路を探さない

**書き込みを利用者や他のセッションに代行させないこと。** 拒否はこのセッションに下りた判断で、
代行はその迂回にあたる。利用者自身が内容を見て保存するのは問題ない（2 がその形である）。

## 5. 書き込み許可ルール

無いと Stop のたびに書き込み許可プロンプトが出て資料作成が中断する
（Remote Control 中は特に致命的）。**実質必須**。

`permissions.allow` に `Edit(.claude-handoff/**)` を追加する（既にあれば何もしない）。

```json
{ "permissions": { "allow": ["Edit(.claude-handoff/**)"] } }
```

ルール名は `Edit(...)` であること（`Write(...)` はファイル権限チェックに使われない）。
書き込み先は `.claude/settings.local.json`（§4 の手順で書く）。

チームで共有したいなら `.claude/settings.json` に置いてもよいが、
**このコマンドは共有側を書き換えない**ので**手で入れてもらう**。
共有側やユーザーレベルに既にあるなら、§4 で重ねて追加しない。

## 6. 閾値設定（`.claude/handoff-config.json`）

**この設定が無いとツールは何もしない。** 必ず作る。プラグイン利用でも、
§1-4 で「設定だけ進める」ことになった場合でも行う。

### 6-1. 値を決める

1. **既にある場合**: **黙って上書きしない**。内容を表示し、**両方**にかける:
   - 6-3 の検証（**未知キーと必須キーの欠落を含む**）
   - **`autocompact_window` がいまの環境の `/context` の総量と一致しているか**の確認。
     **既存の設定でも必ず行う。** 別の環境（例: 500k 環境）で作られた設定をそのまま使うと、
     handoff の閾値に届く前に auto compact が走り、
     **導入は成功して見えるのにツールが実質無効**になる

   両方を通れば「このままでよいか」を尋ね、よければ**変更しない**。
   ただし **`min_margin` / `conservative_fire_pct` が省略されている**なら、
   既定値（10000 / 92）で動いていることを伝え、**明示して書き足してよいか**も尋ねる
   （`setup` は常に5キーを書く。省略は既定値への黙った依存になる）。
   どちらかで落ちたら、**どの条件で落ちたか**を示して修正案を提示し、確認を取ってから書く
   （「既存だから触らない」で温存しない）
2. 無ければ、テンプレ `~/.claude/claude-remote-handoff/handoff-config.json` を**候補**として読む。
   **無条件にコピーしない。** `autocompact_window` がこの環境の `/context` の総量と
   合っているかを確認し、6-3 を通してから書く（テンプレは別の環境で保存された可能性がある）
3. テンプレも無ければ、**`/context` が表示する総量**を尋ねる。
   **モデルの公称ウィンドウではない**ことを明示する
   （例: 1M コンテキストのモデルでも `/context` の表示が 500k なら **500000**）。
   公称値を入れると発火点の計算が実際の2倍になり、閾値に届く前に auto compact が走って
   ツールが実質無効になる
4. 得た `autocompact_window` から提案し、確認を取る:
   - `soft_threshold` = 75%（小数切り捨て） / `hard_threshold` = 85%（小数切り捨て）
   - `min_margin` = 10000 / `conservative_fire_pct` = 92

### 6-2. プラグインの更新手順（案内文）

判定は §2-1 で済んでいる。更新してもらうときは次を案内する
（このコマンドはプラグインを更新しない）:

```
claude plugin update claude-remote-handoff --scope <user|project|local|managed>
```

- scope は `claude plugin list` で確認した値を**必ず指定**する（省略時の既定は `user`）
- **反映には Claude Code の再起動が必要**

### 6-3. 静的検証（`setup` と同一。通らない値は書き込まない）

- **既知の5キー以外を含まない**こと
  （`autocompact_window` / `soft_threshold` / `hard_threshold` /
  `min_margin` / `conservative_fire_pct`）。
  **未知のキーが1つでもあると、実行時にフックが設定全体を拒否する**
  （＝機能が丸ごと無効になる。画面には出ず、エラーログに残るだけ）
- **`autocompact_window` / `soft_threshold` / `hard_threshold` は必須**（欠けると同じく無効）
- `min_margin`（省略時 10000）と `conservative_fire_pct`（省略時 92）は省略しても動くが、
  **5キーすべてを明示して書く**
- `autocompact_window` > 0
- `soft_threshold` > 0 かつ `hard_threshold` > 0 かつ **`soft_threshold` <= `hard_threshold`**（等値可）
- `min_margin` >= 0（**0 は可**）
- `conservative_fire_pct` は **1 以上 100 以下**
- 上記の4つの数値はいずれも **1000000000 以下**（超えると実行時に設定全体が拒否される）
- すべて JSON の**整数**で書く
- 発火点 = `autocompact_window` x `conservative_fire_pct` / 100 の**小数切り捨て**
- **`hard_threshold` + `min_margin` < 発火点** であること。
  満たさない場合は、設定可能な最大の `hard_threshold`（= 発火点 - `min_margin` - 1）を
  示して選び直してもらう

### 6-4. 書き込み

§0-2 の安全確認をしてから、5キーだけを持つJSONとして書き込む（整数。余計なキーを足さない）:

```json
{"autocompact_window":160000,"soft_threshold":120000,"hard_threshold":135000,"min_margin":10000,"conservative_fire_pct":92}
```

新しく値を決めた場合、**同じ内容を `~/.claude/claude-remote-handoff/handoff-config.json` にも
保存**してよいか尋ねる（次のプロジェクトで候補として使える。ただし次回も 6-1 の 2 のとおり
環境に合っているかは確認する）。**この保存先にも §0-2 を適用する。**

## 7. `.gitignore`（gitリポジトリのときだけ）

§0-2 の安全確認をしてから、次の4エントリを追記する。
いずれも**マシン／環境固有**でコミット対象にしてはいけない。

```
.claude-handoff/
.claude/handoff-config.json
.claude/hooks/claude-remote-handoff/
.claude/settings.local.json*
```

- **追記する前に、ファイルの最終バイトが改行かを確かめる。改行でなければ先に改行を足す**
  （`setup.sh` も同じことをしている）。忘れると最初の1行が**前の行に連結される**。
  `.gitignore` が `node_modules/` で終わっていれば `node_modules/.claude-handoff/` という
  1行になり、**`.claude-handoff/` が無視されない**。
  その結果、transcript を含む保存データが `git add -A` でステージされうる
- 既にあるものは追記しない。判定は行頭・行末の
  **半角空白・タブ・復帰（CR）**を取り除いた完全一致で行う。
  **CR を落とすこと**（`setup` も落としている）。Windows でチェックアウトした `.gitignore` は
  行末が CRLF なので、残したまま比べると**どの行も一致せず、実行のたびに4行増える**。
  **1行目の先頭に BOM があれば、それも取り除く**（`setup` も同じ）。
  次の同値形も「既にある」とみなす:
  - ディレクトリ: 末尾スラッシュ付き・無し・末尾がスラッシュ＋アスタリスク、の3形は同値
  - ファイル: 末尾アスタリスクの有無は同値
- **大小は厳密に区別する。** `.CLAUDE-HANDOFF/` を `.claude-handoff/` と同値にしないこと
  （case-sensitive なファイルシステムでは別物で、同値扱いすると
  **`.claude-handoff/` が無視されないまま**になる）
- **ファイル項目への末尾スラッシュは同値としない。**
  `.claude/handoff-config.json/` はディレクトリ専用パターンでファイルを無視しないため、
  これがあっても `.claude/handoff-config.json` は追記する
- **アスタリスクが要る項目にアスタリスクの無い行が既にあった場合は、追記はしないが
  「アスタリスク付きへ更新することを推奨する」と伝える**（`setup` と同じ挙動）。
  とくに `.claude/settings.local.json` は、アスタリスクが無いと
  **§4 が作る退避ファイルをカバーしない**。退避の中身はローカル専用の許可ルールや
  端末固有のパスなので、untracked のまま `git add -A` でコミットに入ると困る
- **不可視文字（NBSP 等）を含む行は同値とみなさない**。見た目が同じでも別の行として扱い、
  紛らわしいので利用者に報告する
- gitリポジトリでない、または git が無い場合はこの手順を飛ばし、その旨を報告する
- 追記対象が**既にgit tracked**なら、gitignore だけでは外れないので
  `git rm --cached` での整理を促す（**自動では行わない**）

## 8. 残りは人の作業（案内して終わる）

自動化できないので、**具体的な値入りで**案内する。

1. `/autocompact <§6 で決めた autocompact_window の値>` を実行する
2. このプロジェクトで一度**対話起動**して workspace trust を承認する
   （未trustではプロジェクト settings.json の許可ルールが無視される）
3. `/hooks` で **5エントリ**（PreCompact / SessionStart x3 / Stop）が見えるか確認する。
   **見えなければ Claude Code を再起動**する。閾値未満のときフックは痕跡を残さないため、
   効いていないことに気づけない

## 9. 報告

最後に次を報告する。**できなかったことを省かない**（不変条件9）。

- **いまフックがどう効いているか**（どこに何組あるか。5つが1組だけになったか）
- **§2 を行った場合**は、導入（または確認）した**版とタグ**。
  プラグインが供給しているならそれは**プラグインの版**である。
  §2 を行っていない場合は**タグを報告できない**ことを書く
  （そのときは、いま使っている手順が最新かどうかも確かめられていない）
- **§1-3 に当てはまるものがあれば必ず書く**
  （`disableAllHooks` で全無効、`jq` が無い、など。
  登録の形が合っていても**動いていない**）
- **§4-1 に当たった場合は、今回予定した settings の変更が未適用であることを書く。**
  §4-1 の 4 のとおり、**既にある登録・足りないままの登録・許可ルールの未適用を分けて**書く
  （一律に「全部動かない」と書かない）。提示したJSONの所在と、適用後に `/hooks` で
  5エントリを確認すること（見えなければ再起動）も併せて伝える。
  復元まで拒否された場合は、**戻せていないことと退避のパス**を必ず書く
- 実施／既存のまま／飛ばした／失敗した、各手順の一覧
- **利用者に残っている作業**（§8 の3つ、手で直してもらう設定など）
